1. REPOSITORY AUDIT & DISCOVERABILITY BASELINE
================================================================================
- Organization: ellmos-ai
- Ecosystem: open-bricks (umbrella)
- Target Audience: Multi-agent AI developers, LLM workflow engineers, autonomous agent fleet operators, system administrators, security officers
- Core Positioning: A local-first pointer registry and one-way materialization engine for AI agent hooks (Claude Code, Codex, Kimi, Antigravity).
- Distinct Value Proposition: Decouples executable hook scripts from private agent configuration directories. Stores canonical scripts in a central, SHA-256-pinned library, enforces fail-closed first-use consent allowlists, provides diagnostic doctor health checks, and materializes hooks strictly one-way without cloud or network requirements.
- Sibling Ecosystem Integration: Architectural companion to `policy-registry` (static rule pointers) and execution sibling to `memoryhooker` and `workflowhooker` (active event interception consumers).

================================================================================
2. TARGET PERSONAS & USER JOURNEYS
================================================================================
1. Multi-Agent System Architects & Fleet Engineers
   - Needs: Manage shared hook scripts across diverse agent frameworks (Claude Code, Codex, Kimi, Antigravity) without directory coupling or path confusion.
   - Pain Points: Agent A's configuration file hard-points to a script in Agent B's private config directory (e.g. Codex pointing at `~/.claude/hooks/guards.py`), causing broken paths across multi-machine environments.
   - hook-master Solution: Canonical source scripts live in `library/` or custom repositories, mapped via pointer entries to each agent's native configuration path, verified by SHA-256 digests.

2. Autonomous AI Agent Operators & Security Officers
   - Needs: Enforce strict trust boundaries and explicit consent before executable code is placed where an agent runtime will automatically execute it.
   - Pain Points: Inadvertent script tampering or uncontrolled automatic hook deployment can lead to unauthorized code execution during tool calls or prompt submissions.
   - hook-master Solution: Fail-closed first-use consent allowlist (`~/.hook-master/allowlist.json`), one-way copy direction (`canonical -> deployed`, never reverse), and deep syntax verification (`py_compile`).

3. Infrastructure & DevOps Engineers
   - Needs: Inspect drift between canonical hook definitions and deployed agent copies, run automatic integrity diagnostics, and benchmark hook execution overhead.
   - Pain Points: Deployed scripts get modified ad-hoc on individual machines, drifting silently from canonical source control.
   - hook-master Solution: `hook-master diff` and `hook-master doctor [--timing]` report hash divergence, syntax errors, missing target config files, and execution timing benchmarks.

4. Privacy, Compliance & Open-Source Governance Teams
   - Needs: Verify zero external network egress, unprivileged execution, permissive licensing, and enforceable security response SLAs.
   - Pain Points: Complex agent toolchains often introduce opaque telemetry or restrictive copyleft dependencies.
   - hook-master Solution: 100% Local-First / Zero-Egress, unprivileged `RunAsInvoker` mode, clean Level 1 SBOM in `THIRD_PARTY_LICENSES.md`, and binding 48h response / 5-day triage SLAs.
